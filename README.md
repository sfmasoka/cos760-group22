## 1. Project Overview

We build a binary classifier that distinguishes human-authored from
machine-generated text in four African languages. The dataset combines
formal text from the DSFSI **Vuk'uzenzele** government-newsletter corpus
(Xhosa, Zulu, Sepedi) with informal social-media text from
**AfriSenti** (Swahili). Machine text is generated by two production
LLMs (**LLaMA-3.3-70B** via Groq and **Gemini-2.5-Flash** via the
Google GenAI API) across 20 task types, 20 domains, and 7 length styles.

**Headline result:** A fine-tuned `Davlan/afro-xlmr-base` classifier
achieves macro F1 = **0.9558** overall and passes the per-language
target of ≥0.80 for all four languages.

The project answers four research questions:

- **RQ1** Which classifier performs best at detecting machine-generated
  text across African languages?
- **RQ2** How effectively can the model transfer zero-shot to unseen
  African languages?
- **RQ3** Which linguistic features distinguish machine from human text?
- **RQ4** How does performance vary across languages and datasets?

## 3. Setup Instructions

There are **two ways** to interact with this project:

### Option A — Run the notebook (full pipeline, Google Colab)

The notebook was developed end-to-end on Google Colab with Drive
mounted. This is the path that reproduces every result in the report.

1. Upload `notebooks/nlp_project_final.ipynb` to Google Colab.
2. Mount Google Drive (the first code cell does this).
3. Create the following folder in your Drive:
   ```
   /MyDrive/COS760_Group22_Project/
   ├── data/{raw, processed, generated}/
   ├── models/
   ├── results/
   └── repos/
   ```
   *(The notebook also creates these automatically if missing.)*
4. Provide API keys when prompted:
   - **Groq API key** — from <https://console.groq.com/>
   - **Gemini API key** — from <https://aistudio.google.com/apikey>
5. Set the Colab runtime to **GPU** (T4 is sufficient).
6. Run all cells. Total runtime: ≈45 min on a T4 GPU.

### Option B — Run the Streamlit demo locally (inference only)

A standalone demo that loads the trained models and classifies any
text the user enters. No GPU or API keys required.

```bash
# 1. Clone the repo
git clone https://github.com/sfmasoka/cos760-group22.git
cd cos760-group22

# 2. Create a virtual environment (Python 3.10 or 3.11 recommended)
python -m venv .venv
source .venv/bin/activate         # Mac/Linux
# .venv\Scripts\activate          # Windows

# 3. Install dependencies
pip install -r requirements.txt
```

**4. Download the trained models** from our shared Google Drive folder:

> *<insert your Drive link here>*

The download contains two items. Place them inside the `models/` folder
in the repo so the final structure looks like this:

```
cos760-group22/
└── models/
    ├── afroxlmr_detector/
    │   ├── config.json
    │   ├── model.safetensors
    │   ├── tokenizer.json
    │   └── tokenizer_config.json
    └── tfidf_lr_baseline.pkl
```

If the downloaded folder is named differently (e.g. `afroxlmr_detector_final`),
rename it to `afroxlmr_detector`.

**5. Run the demo from the repo root:**

```bash
streamlit run src/app_v2.py
```

> ⚠️ Run streamlit from the repo root (not from inside `src/`), or it
> will not find `models/` and `africa.jpg`.

The app will open at `http://localhost:8501`. Choose a model from the
dropdown, paste some text, and click **Analyse text**.

## 4. Running the Code — Step-by-Step

### 4.1 Reproducing the headline results (notebook)

Each section of `nlp_project_final.ipynb` is self-contained and saves its
outputs to `results/` and `models/`. Run them in order:

| Section | What it does | Outputs |

| S5 | Fine-tune AfroXLMR (3 epochs on T4 GPU) | `models/afroxlmr_detector/`, `results/afroxlmr_test_predictions.csv` |
| S6 | Full model comparison | `results/model_comparison_full.csv`, `results/per_language_f1_comparison.png` |
| S7 | Cross-lingual transfer (4 LR scenarios + 2 AfroXLMR scenarios) | `results/{lr_transfer_results,cross_lingual_transfer_summary}.csv` |
| S8 | SHAP explainability | `results/shap_lr_top_features.csv`, `results/shap_lr_summary.png` |
| S9 | Linguistic feature analysis (Mann-Whitney U, Pearson r) | `results/linguistic_*.csv`, `results/linguistic_*.png` |
| S10 | Consolidated findings summary | Console output |

> **Skipping ahead:** If you only want to run the evaluation / SHAP /
> linguistic sections, run S0, S3 (cell 24 reloads the splits from disk),
> then jump to S5 cell that loads the saved checkpoint.

### 4.2 Streamlit demo

```bash
streamlit run src/app_v2.py
```

The app takes a text input, runs it through both the baseline and

## 6. Reproducibility

### Software versions

- **Python:** 3.10 or 3.11 (developed on Colab's Python 3.12)
- **Key packages** (see `requirements.txt` for the full pinned list):
  - `torch` ≥ 2.0
  - `transformers` ≥ 4.40
  - `datasets` ≥ 2.20
  - `scikit-learn` ≥ 1.3

  - `streamlit` ≥ 1.30 (for the demo app)

`Trainer`'s default seeding. Results should reproduce to within
~0.5% macro F1 on a different GPU.

- **Notebook training:** 1× NVIDIA T4 GPU (Google Colab free tier).
  Total runtime ≈45 minutes for the full pipeline (excluding LLM
  generation, which depends on API rate limits).

## 7. Results Snapshot

Full results are in `results/`. Top-line numbers:

**RQ1 — Overall test-set performance**

| Model | Accuracy | Macro F1 | AUC-ROC |
|---|---:|---:|---:|
| TF-IDF + LR | 0.9279 | 0.9241 | 0.9715 |
| AfroXLMR | **0.9577** | **0.9558** | **0.9885** |

**RQ4 — Per-language macro F1 (AfroXLMR)**

| Sepedi | Swahili | Xhosa | Zulu |
|---:|---:|---:|---:|
| 0.9319 | **0.9899** | 0.9642 | 0.9520 |

All four languages pass the ≥0.80 per-language target.

**RQ2 — Cross-lingual zero-shot transfer (key scenario)**

Training on Nguni (Xhosa + Zulu), testing on Sotho-Tswana (Sepedi):
- TF-IDF + LR: F1 = 0.3706 (collapses below random)
- AfroXLMR: F1 = **0.8967** (multilingual pre-training bridges the gap)

## 8. Limitations

- Machine text covers only LLaMA-3.3-70B and Gemini-2.5-Flash. GPTZero
  was intended as a third baseline but was excluded due to API access
  constraints.
- The dataset covers four of Africa's 2,000+ languages.
- Swahili human text comes exclusively from Twitter (informal register).
- Per-language test sets contain 108–180 instances, limiting statistical
  power for per-language metric comparisons.
